---

## 1. Qué es y qué no es esta baseline

| | |
|---|---|
| **Sí es** | un punto de retorno reproducible: un commit exacto, una APK con hash conocido y un conjunto de pruebas registradas |
| **No es** | una release pública. No está en Play Store, no ha pasado Closed Testing, y no ha sido usada por usuarios externos |

La distinción es deliberada. Una **baseline técnica estable** garantiza que se puede volver a un estado conocido y reconstruirlo. Una **release pública** exige además Closed Testing con testers reales, formulario de Data Safety, política de privacidad publicada y las casillas del checklist de release satisfechas — ninguna de las cuales se cumple hoy.

## 7. Deuda y limitaciones conocidas

### 7.1 Discrepancia de versión — la más visible

La etiqueta se llama `v0.3.0-rc.1`, pero la aplicación declara **`0.1.0`** en `package.json`, `app.config.ts` y `build.gradle`, con `versionCode 1`.

**La etiqueta marca un punto del historial de git, no una versión de aplicación.** La casilla del checklist «`mobile/package.json` versión actualizada a `0.3.x`» sigue **sin cumplir**. Debe resolverse antes de cualquier release pública, y exige decidir el esquema de versionado (`appVersionSource: remote` está declarado en `eas.json` pero no hay versiones remotas configuradas).

### 7.2 Limitaciones estructurales heredadas de la auditoría 2026-07-28

Siguen abiertas. La baseline no las resuelve:

- **El vídeo no saca evidencia del dispositivo durante la grabación** (GC-AUD-001). Genera y encola el material después de detener la captura. Ante kill o pérdida del dispositivo mientras se graba vídeo puede perderse toda la evidencia.
- **No existe `capture_end_reason`.** El sistema no puede distinguir una captura terminada limpiamente de una truncada. Fases E-1/E-2/E-3.
- **Recovery I5c** (automático tras reinicio del dispositivo, sin abrir la app) no está implementado.
- **Cifrado local** no implementado; sólo un `TODO`.

### 7.3 Ambigüedades UX residuales de A-2

- **Banner verde genérico.** Se dispara por cualquier entrada cerrada de la cola que un polling observe completamente confirmada, y su texto no identifica la sesión. Puede aparecer mientras se graba otra captura. Dos vías de activación distintas (efecto sobre `guardianStatus` y detector por cola) producen un resultado visual idéntico.
- **Carrera polling ↔ `reap`.** Home lee `GC_QUEUE` cada 500 ms; el worker puede ejecutar `reapEntry` antes del siguiente tick, de modo que una entrada protegida puede desaparecer sin ser observada. Protección lógica y observación por polling no son equivalentes.
- **Sesión cerrada, asentada e incompleta** (fragmentos `uploaded` sin `remote_reference`, sin activos ni fallidos) cae en `Listo` sin informar de que queda evidencia sin confirmar.

Detalle normativo en `PROTECTION_MODEL.md` y `UI_SCREENS.md` §14.

### 7.4 Deuda de la propia ReliabilityCard

- Rama **Android 13+** sin ejercitar (§4.3).
- El botón legacy de exención de batería en Ajustes coexiste a propósito con la tarjeta nueva; su retirada está diferida.
- La tarjeta **desplaza el botón principal hacia abajo** en Home. Sigue visible y dominante, pero ya no centrado.

### 7.5 Infraestructura

- **Sin CI.** Los 198 tests se ejecutan en la máquina del desarrollador; no hay verificación reproducible independiente.
- `npm ci` **falla** sin `--legacy-peer-deps`: el lockfile no materializa los peers `react-dom` y `scheduler`. El perfil `preview` de `eas.json` ya declara `NPM_CONFIG_LEGACY_PEER_DEPS=true`.
- 29 vulnerabilidades reportadas por `npm audit` (1 baja, 17 moderadas, 8 altas, 3 críticas). No se ha ejecutado `npm audit fix`.
- El proyecto EAS anterior (`65029e8e-1af4-4070-80ce-4d6a1b4baa01`) quedó inaccesible y fue abandonado.
- Tres ficheros basura versionados en la raíz del repositorio: `table-nas-routing`, `tash push -u -m wip remaining mobile assets docs`, `tash show --stat`.

## 8. Criterios de rollback

**Volver a esta baseline:**

```bash
git checkout v0.3.0-rc.1
```

La APK correspondiente se reinstala con `adb install -r` sobre cualquier build firmada con el mismo keystore `mdzaYNbPtv`, sin desinstalar ni perder datos locales. Verificar antes el SHA-256 contra §2.

**Revertir sólo la ReliabilityCard**, conservando A-1/A-2 y la configuración EAS:

```bash
git revert 3303f47
```

**Revertir sólo la configuración EAS**, conservando el producto:

```bash
git revert 5ac4a03
```

Los dos commits se mantuvieron separados precisamente para permitir esto.

**Cuándo hacer rollback.** Si aparece cualquiera de estas condiciones, volver a la baseline antes de diagnosticar:

- pérdida de evidencia ya confirmada fuera del dispositivo;
- `GC_QUEUE` corrupta o no rehidratable al arrancar;
- recovery que no drena tras kill o reinicio;
- la app afirma protección sin `remote_reference` real;
- arranque que no llega a Home.
